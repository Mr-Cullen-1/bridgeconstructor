# Viewport 3D Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans for native implementation. User explicitly requested implementation followed by their visual review; do not insert a separate approval gate.

**Goal:** Scroll-free adaptive Bridge Master with a real 3D world and accessible 2D controls.
**Architecture:** Keep pure game engine and reducer. Three.js owns scene resources, rendering and ambient animation; React owns controls and accessible projected node/edge hit targets. Game outcomes remain deterministic.
**Tech Stack:** Existing React/Vite plus Three.js; local procedural geometry, no remote model or texture dependency.
**Spec:** User request and two screenshots on 2026-11-12 supersede original spec's SVG-only and page-scroll presentation constraints. Chosen user-authorized option: approximately 80% 3D scene / 20% 2D HUD, not a percentage of code or exact pixel quota.

## Constraints and review focus
- Fit 1366×768, 1920×1080, 360×800, 390×844 and 800×360 without document scroll or hidden core controls.
- Geometry: terrain/cliffs, moving water, trees, bridge deck/supports, moving vehicle, lighting/shadows; accessible interaction layer stays 2D.
- Camera presets and pointer orbit preserve alignment of projected controls; 44px node targets.
- Pause, hidden tab, reduced motion, unmount and WebGL failure must be handled explicitly.
- Existing five levels, scores, budgets, callbacks and keyboard/touch behavior remain intact.
- No server, persistence, production deployment or real-device QA claims.
